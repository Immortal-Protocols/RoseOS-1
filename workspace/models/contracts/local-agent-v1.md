# local-agent-v1

The boundary between the Rose Models Android host (Java: UI, HTTPS, timers, app launch) and the
portable Rust agent in `workspace/models/rose-chat-core/src/agent.rs`. The agent is a pure state
machine: it does no I/O and reads no clock. The host feeds it **inputs** and carries out the
**outputs** it returns. Exact JSON for every message is in `local-agent-v1.examples.json`. That
file is generated by `cargo run --example local_agent_trace` and checked by `tests/agent.rs`.
Its inference bodies are fixtures, not model output.

## Host surface

```text
create(config_json)  -> handle       Agent::from_config_json
step(handle, input)  -> output_json  Agent::step_json
destroy(handle)                      drop(Agent)
```

`step` returns `{"contract":"local-agent-v1","outputs":[...]}`. Carry out the outputs in order.
`step` never panics on bad input: unparseable JSON returns one `rejected` output, and state is unchanged.
Build the Android library with `--no-default-features`, which drops the desktop `ureq` HTTP transport and the CLI. The agent needs only `serde` and `serde_json`.

## Config

```json
{"contract":"local-agent-v1","model":"muse-glimmer","system_prompt":"Reasoning strength: low",
 "allowlist":[{"app_id":"calculator","label":"Calculator"}],
 "limits":{"max_tokens":512,"max_user_chars":4000,"context_budget_chars":20000,
           "max_reply_chars":8000,"inference_timeout_ms":120000,"tool_timeout_ms":10000}}
```

- **Unknown fields** are rejected.
- **`limits`:** optional. Each field defaults to the value shown.
- **`model`:** the exact served id. A reply reporting another model fails the turn with `model_identity_mismatch`.
- **`allowlist`:** apps the phone has already resolved locally.
  - `app_id` is opaque, matches `[a-z][a-z0-9_]{0,31}`, and must be unique.
  - `label` is 1–64 printable characters.
  - The model only ever sees and returns these ids. The host maps an id to a component it resolved itself. The model never supplies a package, Intent, component, extras or URI.

## Inputs (`type`)

| Input | Fields | When |
| --- | --- | --- |
| `start_turn` | `turn_id`, `text` | Send. `turn_id` is `[A-Za-z0-9_-]{1,64}` and is never reused |
| `inference_response` | `turn_id`, `generation`, `status`, `retry_after?`, `body` | The raw HTTP status and body for a `need_inference` |
| `inference_failed` | `turn_id`, `generation`, `kind` | No HTTP response. `kind` is one of `connect`, `timeout_connect`, `timeout_response`, `tls`, `response_too_large` |
| `tool_result` | `turn_id`, `generation`, `action_id`, `status` | **Exactly one** per `need_tool`. `status` is one of `launch_requested`, `not_found`, `locked`, `not_allowed`, `cancelled`, `failed`. There is no `detail` field (unknown fields are rejected), so send any platform error text to the UI only. A platform exception or other platform error maps to `failed` |
| `cancel` | `turn_id` | Stop |
| `backgrounded` | — | The activity left the foreground |
| `continue` | `turn_id` | The user continues a parked turn after returning |

## Outputs (`type`)

| Output | Host action |
| --- | --- |
| `need_inference {turn_id, generation, body, timeout_ms}` | POST `body` (complete OpenAI-compatible chat-completions JSON) to the configured URL with platform TLS and the configured auth. Answer with one `inference_response` or `inference_failed` carrying the same `turn_id` and `generation` |
| `cancel_inference {turn_id, generation}` | Abort that request. Its reply is rejected anyway |
| `need_tool {turn_id, generation, action_id, tool:"open_app", app_id, timeout_ms}` | Immediately before launching, check that this turn is still active and that the activity is foreground and unlocked. Launch the locally resolved app, or report `cancelled`, `locked`, `not_found` or `not_allowed`. Report `failed` after `timeout_ms`. Always send exactly one `tool_result` |
| `render {turn_id, event}` | Update the UI. `event.kind` is one of: `status` (`thinking`, `awaiting_app`, `parked`); `assistant_text`; `tool_proposed`; or `tool_result` with `after_stop` |
| `turn_ended {turn_id, outcome, error?}` | `outcome` is one of `completed`, `cancelled`, `failed`, `superseded` |
| `rejected {reason}` | The input did not match live state and was ignored. Nothing changed |

## Rules

- **One turn at a time.** `start_turn` while a turn is active is rejected with `turn_active`. A new `start_turn` while a turn is parked ends that turn as `superseded`; its tool record stays in the history.
- **Limits:** at most **2 inferences** and **1 `open_app`** per turn. A second proposal fails the turn with `action_limit`.
  - Every emitted `need_inference` counts toward the 2, **including one later cancelled** by Stop or background. Nothing refunds it.
  - A host must dispatch only the `need_inference` outputs it receives. It must never re-send a stored request body itself, for example on Continue.
- **Model answer:** the whole content must be exactly one JSON object.
  - Final text: `{"rose_action":"local-agent-v1","type":"final","text":"..."}`
  - Open an app: `{"rose_action":"local-agent-v1","type":"open_app","app_id":"..."}`
  - **When:** `open_app` only when the user explicitly asks to open or launch an app. Anything else, including a question the model can answer itself, is `final`. The instructions state this (`OPEN_APP_POLICY` in `rose-chat-core/src/agent.rs`). The agent still accepts an allowlisted `open_app` on any turn, so an unrequested one is caught by conformance (`open_app_outside_launch_prompts`), not hidden.
  - Prose, code fences, arrays, concatenated objects, duplicate or unknown fields fail the turn with `malformed_action`. An unknown `type` fails it with `unknown_action`. An id not on the allowlist fails it with `action_not_allowed`.
  - A truncated reply fails the turn with `truncated_reply`.
  - In every failure case nothing is executed.
- **Authority:** only `tool_result` from the platform records what happened.
  - The next request carries that result as a user-role message, `{"rose_event":"tool_result",...}`.
  - User text always travels as a JSON string inside `{"rose_event":"user_message","text":...}`, so typed text can never form a tool-result event.
  - Model text claiming an app opened changes nothing.
- **Fencing:** every input must match the live `turn_id` and `generation`, and `action_id` for tools. Otherwise it is rejected as stale or duplicate.
- **Stop (`cancel`):**
  - during inference: `cancel_inference`, then `turn_ended cancelled`; the history is unchanged.
  - during a tool dispatch: `turn_ended cancelled`. The one receipt for that dispatch is still accepted afterwards and rendered with `after_stop: true`. A launch may already have happened and cannot be undone.
  - when parked: the turn ends.
- **Background:**
  - during the first inference: `cancel_inference`, then `turn_ended cancelled`, with error `backgrounded`. Nothing is recorded.
  - during a tool dispatch: the result is recorded when it arrives, and the turn parks without a new request (`render status parked`). `continue` then emits the turn's second and last request.
  - during the post-tool inference: `cancel_inference`, then `turn_ended cancelled` with error `inference_limit`. That request has already used the second slot, so the turn cannot park. `continue` is rejected (`no_parked_turn`). The tool record stays in the history, and the next Send starts a new turn with a fresh budget that sees it.
  - No automatic resume and no background work. Repeated background/Continue can never produce more than two `need_inference` outputs for one turn.
- **History:** a completed turn commits its messages. A tool result commits the turn so far, because the action is a fact. A failed or cancelled turn leaves no other trace.
- **Character budget:** `context_budget_chars` is checked before every request; exceeding it gives `context_limit`. `max_reply_chars` gives `reply_too_long`. Token limits are the server's (8,192 total, `max_tokens` 512).
- **HTTP error kinds** match the CLI: `unauthorized`, `forbidden`, `not_found`, `rate_limited`, `bad_request`, `server_context_limit`, `server`, `unexpected_status`, `malformed_response`, `empty_completion`.
- **No hidden reasoning:** a separate `reasoning` field is ignored; it is never shown or replayed.
