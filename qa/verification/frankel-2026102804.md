The beta source and OS delta configure no default HOME role holder (`git grep`
for role/defaultHome in `os/` and `scripts/` at `ae9cfd4d`: none). Which app
holds HOME is decided on the device. That needs `runtime-readonly` (HOME role
holders) on the phone, and this record does not claim it.

**Source (`ae9cfd4d`):**
- **Pages:** `MainActivity` builds the launcher pages `Home` (index 0,
  `RoseHomeView`), `Voice home` (1, the legacy PlayfulTheme microphone page) and
  `Widgets` (2), then app pages.
- **HOME intents:** `showHomeFor` selects page 0 only for intents with
  `CATEGORY_HOME`.
- **Every other entry**, including the launcher icon, opens `voicePage`
  (`selected = … : voicePage`).
- **Rose presence:** `Open Rose` starts `RoseConversationActivity`.
- **Unpaired device:** `MainActivity.onCreate` starts `PairingActivity` when the
  device is unpaired.

**Prediction for runtime checks:** when another app holds HOME, the Rose Fold
Home is never shown, and opening Rose Agent from an icon shows the legacy Voice
home. This is a source-backed prediction, not an observation. The OS Manager
owns the product correction (OS-HOME-2804-FIX-001).
